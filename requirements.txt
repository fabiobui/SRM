# Reconstructed from the production venv's `pip freeze` (Ubuntu 24.10 VM, Python 3.12.7,
# /home/redmine/SRM/.venv) on 2026-09-15. The previous requirements.txt was a stray
# `pip freeze` of the VM's *system* Python (dbus-python, PyGObject, launchpadlib, etc.) and
# was missing Django itself plus most of the app's real dependencies — it could not boot.
#
# `mod_wsgi` is intentionally omitted: it's only needed to embed the app inside Apache in
# production (confirmed via `apache2ctl`/mod_wsgi config on the VM) and requires Apache dev
# headers to build; local/dev here runs via the Django/Werkzeug dev server instead.
#
# Two deliberate deviations from the exact prod pip freeze, both to make this one file
# installable on native Windows (Python 3.12, matching prod) with zero C build tools:
#   - mysqlclient bumped 2.2.0 -> 2.2.7 and argon2-cffi-bindings bumped 21.2.0 -> 26.1.0:
#     same PyPI wheel-only patch-level bump, but the pinned versions above never shipped
#     Windows wheels for cp312, so pip tried (and failed) to compile them from source.
#     2.2.7/26.1.0 do ship cp312 win_amd64 wheels. No functional/behavior change.
#   - django-auth-ldap/python-ldap marked `sys_platform != "win32"`: python-ldap has NEVER
#     published a Windows wheel (sdist-only, needs the OpenLDAP SDK + a C compiler to build),
#     so pip skips both on Windows. This is safe because config/settings.py only imports them
#     when LDAP_ENABLED=True, and local dev always keeps LDAP_ENABLED=False (see CLAUDE.md) —
#     Linux/Docker/prod (LDAP_ENABLED=True there) still install and use them normally.
